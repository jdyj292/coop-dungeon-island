사람이 읽는 안내서입니다. Claude Code용 규칙은 `CLAUDE.md`에 있습니다.

## 처음 한 번
1. 이 폴더를 git 저장소로 만들고 첫 커밋: `git init && git add . && git commit -m "설계 문서와 데이터"`
2. Node 20 이상, pnpm 설치 (`npm i -g pnpm`)
3. 폴더에서 `claude` 실행

BGM 미리 듣기: 폴더에서 `npx serve .` → 브라우저로 `/tools/bgm-preview/` 열기

## Claude Code 진행 방법

**원칙: 한 세션 = roadmap.md 3장의 한 줄.** 끝나면 확인 → 커밋 → `/clear` 후 다음 줄.

### 매 작업의 흐름
1. 요청: `roadmap 0-1 진행해줘`
2. Claude가 계획(바꿀 파일, 확인 방법)을 보여주면 검토 후 승인. 큰 작업은 Shift+Tab으로 plan 모드를 켜고 요청하면 더 안전
3. 끝나면 Claude가 요약하고 CLAUDE.md "현재 상태"를 고침
4. 직접 확인 (`pnpm dev`, `pnpm test`, 미리보기 도구)
5. 커밋: `0-1 완료 커밋해줘`
6. `/clear`로 대화를 비우고 다음 작업 (문서는 CLAUDE.md가 다시 안내하므로 맥락을 이어갈 필요 없음)

### 요청 예시
| 상황 | 이렇게 말하기 |
|---|---|
| 다음 작업 | `roadmap 0-3 진행해줘. 계획 먼저 보여줘` |
| 그림·소리 | `sprite-preview로 보여줘. 승인하면 데이터에 반영해` |
| 승인본과 비교 | `docs/refs/approved/character_weapon_poses.png와 비교해서 다른 점 알려줘` |
| 막혔을 때 | `지금 상태 요약하고, 원인 후보 3개와 확인 방법 알려줘` |
| 설계를 바꿀 때 | `이렇게 바꾸고 싶어: ... 영향받는 문서와 데이터부터 정리해줘` |
| 세션이 길어졌을 때 | `/compact` 또는 커밋 후 `/clear` |

### 주의할 점
- **그림·색·소리는 반드시 미리보기로 보고 승인.** 승인 원본(docs/refs, tools/*/reference*.html)은 Claude가 고치지 않게 되어 있습니다
- 한 번에 여러 작업을 맡기지 마세요. 작은 단위일수록 결과가 정확하고 토큰도 덜 듭니다
- Claude가 문서와 다르게 만들었으면 "문서 기준으로 고쳐줘" 또는 "문서를 이렇게 바꿔줘" 중 하나를 고르세요
- 마일스톤이 끝나면 CLAUDE.md "개발 순서" 체크와 다음 마일스톤 작업 목록 추가를 요청하세요 (`M2 작업 단위를 roadmap 3장에 추가해줘`)
