# 모션 (docs/motion.md)

캐릭터·몬스터 움직임을 스타일리시하게 만드는 규칙. 승인된 기준은 "대검 3연타 스타일리시 비교 데모"(2026-10).
히트스톱·흔들림 시간 값은 docs/combat.md 5장, 행동 구간 길이는 shared/data, 이펙트 모양은 docs/art.md 7장.

**원칙: 그림 수보다 타이밍과 반응.** 같은 포즈 그림이라도 리듬·타격 패키지·피격 반응·따라오는 움직임으로 액션감을 만든다.

---

## 1. 리듬 (포즈 유지 시간)

- 프레임을 균일하게 넘기지 않는다. **준비는 길게 멈추고 → 타격은 순간 → 마무리는 길게 유지**
- 행동 구간과 연결: windup = 준비 포즈 유지, active 첫 1~2프레임 = 스미어, 나머지 active·recovery = 공격 포즈 유지
- 강한 공격일수록 준비를 더 길게 (예고가 곧 무게감). 연타의 마지막 타는 준비 시간을 앞 타보다 늘린다
- 위치 보정: 준비 때 1px 뒤로, 타격 때 2~3px 앞으로 (데이터 move와 별개의 연출용 오프셋, 판정에는 영향 없음)
- 기준 예 (대검 3연타, 데모 값): 1·2타 준비 0.12초 / 3타 준비 0.24초, 마무리 유지 0.2~0.45초
- 실제 구간 길이·포즈는 weapons.json이 기준. M0 0-7에서 데모 타이밍으로 확정 (1·2타 windup 0.12초, 3타 0.24초). 포즈는 타마다 다르게 (2026-10): 1타 ready → slash(내려베기), 2타 draw → sweep(가로베기), 3타 heave → rise(양손 올려베기, 데모의 low → up)
- 3타는 설계대로 knockback (데모는 3타가 띄움). 띄우기·바운드·다운은 올려베기 스킬(gs_launch)로 확인 (0-6 결정)

## 2. 스미어

- 무기 궤적은 초승달 스미어 1장으로 표현 (중간 포즈를 그리지 않는다)
- 앞으로 뻗는 공격(대검 대시 등)은 초승달 대신 칼날 줄을 따라가는 직선 스미어(찌르기)를 쓰고, 돌진하는 캐릭터를 따라간다. 대상 행동은 fx.json smear.thrust.actions
- 0.06초 동안 꼬리부터 사라짐. 강한 공격은 반지름·두께를 키운다
- 모양·색은 art.md 7장

## 3. 타격 패키지 (같은 프레임에 동시에)

적중 판정이 나는 프레임에 아래를 **한꺼번에** 실행한다. 따로 나오면 흐려진다.

| 요소 | 약 | 강 |
|---|---|---|
| 히트스톱 | combat.md 5장 | combat.md 5장 |
| 흰색 번쩍임 | 2프레임 | 4프레임 |
| 타격 섬광 | 십자 별 2프레임 + 불꽃 6개 | 같음 + 크게 |
| 대상 반응 | 4장 피격 반응 | 4장 피격 반응 |
| 화면 흔들림 | 없음 | 정수 1~2px, 히트스톱 + 0.12초 |
| 데미지 숫자 | 2배 크기로 튀었다 1배로 | 3배 → 2배, 금색 |
| 효과음 | hitLight | hitHeavy (docs/audio.md) |

- 중(medium, 스킬): 강 열과 같은 구성에 흔들림만 1px, 숫자는 금색 2배 (0-6에서 이대로 구현, 승인 대기)

- 코드에서는 `hitPackage(grade, target, point, damage)` 하나로 묶어 호출 (client/src/fx/hitPackage.ts). 번쩍임 프레임·섬광·숫자·스미어·리듬 값은 client/data/fx.json
- 히트스톱 동안 게임 시간은 멈추고 흔들림만 진행. 번쩍임·섬광·스미어·숫자는 멈춘 채 보이고 히트스톱이 끝난 뒤 남은 시간을 쓴다 (승인 데모와 같음)

## 4. 피격 반응 (몬스터·플레이어 공통)

| 반응 | 표현 |
|---|---|
| 약 | 피격 프레임(찌그러짐 + 질끈 감은 눈) 0.1초 + 뒤로 3~4px 미끄러짐 |
| 강 | 피격 프레임 + 뒤로 크게 밀림 + 먼지 |
| 공중 | 늘어난 피격 프레임, 0.08초마다 90° 회전 |
| 바운드 | 착지 순간 찌그러짐 + 먼지 + 작은 튀어오름 |
| 다운 | 눕힘(90°) + 6px 미끄러짐 + 충격 링 + 짧은 흔들림 |
| 기상 | 찌그러짐 1회 후 대기 |
| 기절 | 눕힘(90°, 피격 프레임) 상태로 깜빡이다 퇴장 (fx.json reaction.stunBlink) |

- 몬스터 스프라이트에 피격 프레임 `hurt`(찌그러짐)와 `hurtAir`(늘어남)를 추가한다 (sprites.md 6장). 없으면 windup 프레임으로 대체
- 슈퍼아머 중에는 반응 없이 번쩍임만

## 5. 따라오는 움직임 (코드로, 그림 추가 없음)

- 스카프 꼬리: 목 뒤에서 2~3픽셀이 몸보다 늦게 따라오며 흔들림 (이전 위치로 35%씩 다가감 + 작은 사인 흔들림)
- 망토·묶은 머리: 같은 방식
- 잔상: 백스텝·대시·돌진 스킬에서 0.04초마다 반투명(35%) 잔상, 0.18초 동안 사라짐 (fx.json afterimage, client/src/fx/afterimage.ts). 백스텝 높이 오프셋은 fx.json backstepHop
- 먼지: 달리기 시작, 방향 전환, 착지, 바운드, 다운

## 6. 이동·상태 모션

- 프레임 목록은 art.md 4장 "이동·상태 모션"
- 달리기: 시작할 때 먼지 + 앞으로 기울이기 1프레임, 멈출 때 미끄러지며 먼지
- 방향 전환: 돌아서는 프레임 0.05초 + 발밑 먼지
- 백스텝: 2프레임 + 잔상 (5장), 착지 때 찌그러짐 1회
- 피격·다운·기상: 4장 피격 반응과 같은 규칙을 플레이어에도 적용. 모션 그림은 art.md 4장 (hurt·down·getup·knocked), 기상·부활 무적 = 깜빡임
- 모션 고르는 순서: 쓰러짐 > 우물에서 떨어짐·착지 웅크림 > 다운 > 피격 > 기상 > 백스텝 > 공격 포즈 > 방향 전환 > 달리기 > 걷기 > 숨쉬기 (client/src/view/playerView.ts)
- 점프는 없다 (combat.md). 뛰어오름은 스킬 연출과 우물 입장·복귀로만
- 우물 뛰어들기 (섬, island.md 6장): 0.45초. 앞 70%는 구멍 위까지 포물선(최고 16px, 모션 backstepAir, 우물 앞에 그림), 나머지는 12px 가라앉으며(backstepLand, 우물 뒤에 그려 테두리가 가림) 사라지고 구멍에서 버섯빛 점 6개가 올라옴. 이름표 숨김
- 우물에서 떨어져 착지 (던전 층 첫 방): combat.json arriveSec(0.5초) 동안 110px 위에서 가만히 놓은 물체처럼 점점 빨라지며 떨어짐(backstepAir, 그림자는 높이에 따라 작게), 착지하면 0.2초 웅크림(backstepLand) + 먼지(다운과 같은 양)·흔들림·wellLand. 다른 사람의 착지는 먼지만 (client/src/fx/wellArrival.ts dropZ, view/playerView.ts)
- 우물에서 튀어나오기 (섬 복귀): 0.55초. 뛰어들기를 거꾸로 — 구멍 속에서 솟아(빛 점) 포물선(최고 14px)으로 착지 자리에. 값 fx.json wellHop, 구현 client/src/fx/wellHop.ts

## 7. 스킬 모션

- 스킬은 평타 포즈를 그대로 재사용하지 않는다. **자세부터 달라야** 스킬을 골라 쓰는 재미가 생긴다
- 무기마다 스킬 전용 포즈 4~6개를 두고 스킬들이 조합해 쓴다 (목록은 art.md 4장 "스킬 전용 포즈")
- 같은 포즈를 공유하는 스킬은 리듬(준비 길이), 이동, 스미어 크기·색, 이펙트로 구분
- 스킬은 평타보다 준비를 길게, 마무리 자세를 뚜렷하게 (구 던파식 "기술 이름이 보이는" 자세)

## 8. 몬스터 모션

- 예고(windup)는 몸으로 분명하게: 웅크림·떨림·부위 치켜듦. 강 공격일수록 길게
- 공격 순간은 늘어난 프레임 1장 + 스미어나 돌진 먼지
- 이동에도 리듬: 버섯은 튀어오름-착지 찌그러짐, 멧돼지는 2프레임 걷기
- 잠 (층 첫 방, dungeon.md 2장): 대기 그림 + 머리 위 3×3 도트 z 두 개가 번갈아 떠오름(palette floors.1.monster.sleepCloud). 깨어나는 순간 피격 반응으로 움찔 + monWake (같은 순간 여럿이면 소리 하나로 합쳐짐, client/src/fx/wellArrival.ts SleepMarks)
- 구현 (client/src/view/monsterView.ts): 피격 반응 > 어지러움·그로기 > 공격 구간(states `구간:공격id`) > 이동(move) > 대기 순으로 프레임 선택. 프레임의 shake는 좌우 1px 떨림, spin은 90°씩 회전, 슈퍼아머 중 외곽선 금색 깜빡임. 값은 fx.json monster

## 9. 모션 확인 도구 (tools/motion-preview)

- 실행: `pnpm motion-preview` (포트 5175). 게임과 같은 코드(client/src/stage/combatStage.ts)를 대본 입력으로 반복 재생: 3연타 → 스킬 / 3연타만 / 스킬만
- 무기: 대검(스킬 = 올려베기) / 스태프(버섯 4타일 앞, 스킬 = 화염 폭발 → 얼음 장판 → 순간이동 백스텝)
- 재생·일시정지(Space), 한 프레임 넘기기(.), 속도 1 · 1/2 · 1/4 · 1/8
- 슬라이더: 구간 길이(weapons.json·skills.json), 히트스톱·흔들림·띄우기(combat.json), 번쩍임 프레임·리듬 오프셋·스미어(fx.json). 값은 메모리에서만 바뀌고 파일은 그대로
- "데모 타이밍" = 1장 기준 예(1·2타 0.12초, 3타 0.24초)를 한 번에 적용, "원래 값" = 되돌리기
- "JSON 복사": 바꾼 값만 `{ "파일": { "키.경로": 값 } }` 형식으로 복사 (배열 칸은 숫자 키). 승인된 값만 해당 파일에 반영
- 아래에 승인 데모(reference.html, 수정 금지)를 그대로 띄워 나란히 비교
- 수치 튜닝은 이 도구로 직접 하고, 확정 값만 데이터·문서에 반영 (토큰 절약)
