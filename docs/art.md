# 아트 가이드 (docs/art.md)

2D 도트 그래픽의 기준 문서: 화면·투영, 캐릭터 사양, 레이어·장비, 무기 포즈, 자동 음영 규칙, 환경, 이펙트, 색.
연출 타이밍(히트스톱·흔들림 시간)은 docs/combat.md, 층별 분위기는 docs/dungeon.md, 색 값은 client/data/palette.json.

**최우선 원칙: 가독성.** 화려함보다 "지금 무엇이 위험하고, 누가 어디 있고, 무엇을 맞혔는지"가 먼저 보여야 한다.

---

## 0. 아트 디렉션

### 한 줄 콘셉트
**장난감 상자 속 따뜻한 동화 마을, 그 아래 어두운 던전에서 벌어지는 묵직한 모험** — 작고 귀여운 2등신 도트 캐릭터가 큰 무기를 휘두른다

### 키워드
작고 귀여운 · 따뜻한 · 또렷한 실루엣 · 과장된 무기 · 묵직한 한 방 · 밝은 섬과 어두운 던전

### 두 공간의 대비
- 섬: palette.json island 색 그대로 (밝고 따뜻함)
- 던전: 같은 계열에서 배경 명도만 낮춤 (palette.json floors). 캐릭터·몬스터·이펙트 색은 섬과 동일
- 우물로 내려갈 때: 우물 구멍으로 뛰어들어(공중은 우물 앞, 가라앉을 때는 우물 뒤라 테두리가 가림) 버섯빛 점이 올라오고 → 0.6초 동안 어두워진 뒤 던전. 돌아오면 우물에서 튀어나와 우물 앞에 착지 (motion.md 6장, 값 fx.json wellHop)

### 하지 말 것
- 그라디언트 하늘, 사진 질감, 반투명 남발 (빛줄기·비네트만 예외)
- 네온·사이버·호러 톤, 순흑·순백 배경
- 정수가 아닌 배율 확대, 회전·크기 변경으로 생긴 깨진 픽셀(믹셀). 회전은 90° 단위만
- 빨강 계열(색상 350°~15°)을 배경·몬스터 주색으로 사용 (위험 예고 전용)
- 피·잔혹 표현

### 시각 레퍼런스 폴더
- `docs/refs/approved/`: 확정된 캐릭터·화면 캡처. 새 작업의 톤 기준 (목록은 docs/refs/README.md)
- 이미지는 토큰을 많이 쓰므로 필요한 작업에서만 읽는다

## 1. 화면과 투영

### 내부 해상도와 배율
- 게임은 낮은 내부 해상도로 그린 뒤 **정수 배율**로 확대 (nearest, 보간 없음)
- 내부 384×216(가로 24타일) 기준. 배율 = floor(창 너비 / 384), 최소 2. 남는 영역은 시야를 조금 넓혀 채운다. 높이가 186(바닥 끝 190 − 잘라도 되는 맨 위 26 + HUD 22)보다 작아지는 배율은 쓰지 않는다 (client/src/scale.ts, 브라우저 1920×950 → 5배 384×190) (2026-10: 288×162(18타일)은 답답해 보여서 넓힘, 1920px 창이면 6배 → 5배)
- Phaser 설정: pixelArt: true, roundPixels: true

### 벨트스크롤 투영 (던전·섬 공통)
- 로직 좌표(x, y=깊이, z=높이, 단위 px, 1타일 16px) → 화면 좌표
  - 화면 X = x − 카메라X
  - 화면 Y = 바닥 기준선 + y × (10/16) − z
- 바닥 타일은 화면에서 **16×10px** (깊이가 압축되어 보임)
- 깊이 정렬: y가 큰(앞쪽) 것을 나중에 그린다

### 던전 화면 구성 (전투 구역 기준 좌표, 아래 HUD 띠는 화면 맨 아래)
| 세로 구간 | 내용 |
|---|---|
| 0~20 | 벽 위로 보이는 나무·장식 (위쪽 HUD가 겹쳐도 되는 곳) |
| 20~50 | 뒤쪽 벽 30px |
| 50~190 | 바닥 최대 14타일(140px). 방 깊이가 더 얕으면 남는 아래쪽은 어두운 절벽 가장자리 |
| 화면 맨 아래 22px | HUD 전용 띠 (docs/hud.md) |
- 방 깊이 전체가 항상 화면에 들어옴 (세로 스크롤 없음). 전투 영역(20~190)에는 HUD를 두지 않는다
- 화면이 0~190보다 높으면(216이면 194 − 190 = 4px) 남는 세로를 위아래로 반씩 나눠 전투 구역을 가운데에 둔다 (client/src/scenes/Dungeon.ts). 낮으면 맨 위 나무 장식·뒤쪽 벽 윗부분(최대 26px)부터 잘라 바닥 끝이 HUD에 가리지 않게 한다. 방이 화면보다 좁으면 가로도 가운데 정렬
- 카메라 가로 추적: 내 캐릭터 중심, 데드존 ±2타일, 방 경계에서 멈춤
- 보스 등장 연출: 보스 방에 들어가면 카메라가 보스 쪽으로 0.8초(부드럽게 가속·감속) → 이름 띠 1.2초 → 0.6초 동안 돌아옴. 그동안 내 조작 정지 (fx.json bossIntro, client/src/view/bossIntro.ts)
- 화면 흔들림은 정수 픽셀 단위

### 섬 화면
- 같은 투영. 섬 40×30칸 = 내부 640×300px → 가로·세로 모두 추적 (아래 22px은 HUD 띠). 기준은 내 캐릭터 몸 가운데(발에서 10px 위), 데드존 가로 ±40·세로 ±12px (발 기준 ±24였을 때는 위로 한참 올라가야 따라와 위아래가 비대칭)
- 배치 모드에서는 커서를 따라가며, 화면 좌표 → 격자 칸 변환으로 칸 선택
- 섬 그래픽 세부는 6장 "섬"

## 2. 캐릭터 사양

### 비율
- **키 16px, 폭 최대 12px, 2등신.** 머리 9줄, 몸통 4줄, 다리·발 3줄 (외곽선 1px은 바깥)
- 오른쪽을 보는 3/4 시점으로 그린다. 왼쪽은 좌우 반전
- 형태는 모서리를 1px씩 깎아 부드럽게. 손발은 작고 뭉툭하게

### 얼굴
- 눈: 세로 2px 점 두 개 (가까운 쪽 눈이 얼굴 앞쪽)
- 볼터치 1px. 입은 평소 생략, 표정에서만 1~2px
- 표정 3종: 기본(세로 눈), 피격(두 눈 질끈 감은 가로 줄 + 작은 입), 기쁨(두 눈 ^ ^ + 벌린 입). 두 눈은 같은 모양

### 머리 모양
- 짧은 머리, 묶은 머리(뒤로 늘어진 꼬리), 삐죽머리(위로 솟은 끝). 머리색 4종 (palette global.hairColors)
- 고르기: 가입 직후 섬에 처음 들어가면 설정 외형 탭이 열림, 그 뒤에도 섬에서 언제든 Esc → 외형 (hud.md 8장). 번호 순서는 client/src/view/look.ts (서버는 번호만 저장)
- 머리 모양은 윗부분·뒷부분 실루엣으로 구분되게

### 플레이어 구분
- 목의 스카프 한 줄 = 플레이어 색 (palette.json global.playerColors). 발밑 링도 같은 색
- 복면 등 얼굴을 가리는 장비는 스카프 색을 그대로 쓴다

### 기본 의상 (초보 모험가)
- 갈색빛 주황 튜닉 + 벨트, 짧은 바지, 작은 부츠

## 3. 레이어와 장비

### 레이어 원칙
- 캐릭터는 부위별 층(망토, 하의, 상의, 목 장식, 얼굴, 머리, 모자, 팔, 무기)을 겹쳐 만든다
- **층을 모두 합친 뒤 음영·외곽선을 한 번에 입힌다** (5장). 그래서 어떤 조합이든 경계와 광원이 자연스럽다
- 층 순서, 데이터 형식, 합성·캐시 절차는 docs/sprites.md

### 장비 칸
머리 모양(생성 시) · 모자 · 상의 · 하의 · 망토 · 무기

### 장비 표현 원칙
- 16px에서는 색보다 **형태**가 바뀔 때 "옷을 바꿨다"는 느낌이 난다
- 수집 의상의 중심은 실루엣을 바꾸는 장비: 모자, 후드, 망토, 어깨 장식
- 상의·하의는 주색 + 포인트색 두 가지 조합으로 구분
- 의상은 **외형 전용** (능력치 없음). 획득처는 docs/island.md

### 확정된 의상 예시
| 의상 | 구성 |
|---|---|
| 초보 모험가 | 기본 의상 |
| 마법사풍 | 끝이 뒤로 꺾인 챙 넓은 모자(금색 띠) + 남색 로브(금색 띠) |
| 도적풍 | 청록 후드 + 스카프 복면 + 어두운 가죽옷·긴 바지 |
| 기사풍 | 어깨 보호대가 튀어나온 강철 갑옷 + 파란 망토 (빨강 금지 규칙 때문에 파랑) |

## 4. 무기와 포즈

### 무기 크기 (과장)
| 무기 | 크기 |
|---|---|
| 대검 | 날 길이 11px + 손잡이·가드, 폭 2px (거의 키만큼) |
| 스태프 | 키보다 긴 막대 + 끝에 2×2 보석 |
| 주먹 | 손을 2×2 건틀릿으로 |
| 쌍검 | 각 날 5px, 폭 1px, 양손 |

### 포즈 세트 (무기별)
| 무기 | 포즈 |
|---|---|
| 대검 | 대기(앞손으로 쥐고 칼날을 앞으로 수평) · 준비(머리 위로) · 내려베기 · 올려베기 · 평타 2타 뒤로 당김(draw: 어깨 높이 뒤로 수평) → 가로베기(sweep: 한발 내딛고 허리 높이 앞으로, 반대 방향 납작한 스미어) · 평타 3타 낮게 웅크려 양손 뒤로(heave) → 양손 크게 올려베기(rise) |
| 스태프 | 대기(앞손으로 쥐고 보석을 어깨 앞 위로 비스듬히) · 시전 준비(앞으로 기울임) · 마법탄(앞으로 겨눔) · 광역 시전(머리 위, 발밑 마법진) |
| 주먹 | 대기(양팔을 아래로 늘어뜨림) · 가드(양손 올림) · 잽 · 어퍼컷 · 잡기(양손 앞으로) |
| 쌍검 | 대기(두 손 모두 날끝을 앞 아래로, 뒷손 단검은 몸 앞에 그려 다리 앞을 가로지름) · 베기 1(위로) · 베기 2(앞으로, 뒷팔 사용) · 던지기 |

### 스킬 전용 포즈 (무기별 추가, 미확정 — 그릴 때 미리보기 검토)
평타 포즈 4개 + 스킬 포즈 4~6개 = 무기당 약 10개로 스킬 14개를 조합. **MVP 표시**는 MVP 기본 스킬에 필요한 것.

| 무기 | 스킬 포즈 (쓰는 스킬 예) |
|---|---|
| 대검 | **머리 위 치켜들기**(대지가르기·지진·파쇄참 준비, MVP) · **내리꽂고 웅크림**(내려찍기 마무리, MVP) · 허리 옆 쥐기 charge(충전·발도·어깨 들이받기 준비) · 몸 뒤로 감기 spinBack(앞팔을 몸 앞으로 가로질러 칼을 등 뒤 수평으로, 몸 뒤로 1px·웅크림 1: 회전베기·회오리 검기·검기 준비) · 어깨 들이받기 tackle(몸을 앞으로 2px 숙이고 칼은 허리 뒤로 끌림) · 던지기 throwWind(칼을 등 뒤 아래에서 위로 감아 쥠) → throwRelease(앞팔을 앞으로 뻗은 빈손, 뒷팔 뒤로) · 발도 마무리 iai(낮게 웅크려 한 손으로 칼을 가슴 높이 앞으로, 뒷팔 뒤로) · 크게 베어 올림 cleave(한 손으로 칼을 앞 위로, 뒷팔 뒤로: 검기·검흔 베기 마무리, 회오리 검기 후딜레이) |
| 스태프 | 준비(보석 자리에 모으기 빛 spark): 앞 위로 치켜들기 gather(얼굴 오른쪽으로 손을 올려 지팡이를 앞 위로 비스듬히, 뒷손 받침, 몸 뒤로 1px: 화염 폭발·화염구·부유 구슬) · 하늘로 들기 skyRaise(지팡이를 머리 옆에서 곧게 위로: 번개 연쇄·중력 우물·중력장) · 뒤로 당기기 aimBack(지팡이를 등 뒤 허리 높이 수평으로, 보석이 몸 뒤로 나옴: 얼음 창) · 꽂으려 들기 plantRaise(지팡이를 세워 들어 올림: 얼음 장판·불꽃 기둥) · 낮게 퍼 담기 scoop(웅크려 지팡이를 발 앞 낮게 수평으로: 끌어올림). 시전: 앞으로 찌르기 thrust(한발 내딛고 몸 앞으로 1px, 양손으로 지팡이를 가슴 높이 앞으로, 끝에서 발사 섬광 bolt) · 땅에 꽂기 plantDeep(웅크림 2, 지팡이 끝이 땅에 닿음, 그 자리에 마법진 + 충격 stamp) · 양손 앞으로 뻗기 channel(지팡이를 앞 위로 내밀고 발밑 마법진: 부유 구슬·중력 우물) · 올려 휘두르기 upswing(지팡이를 앞 위로 쳐올림: 끌어올림). 평타 마법탄은 ready → bolt 그대로. 휘둘러 치기(근접 밀어내기)는 쓰는 스킬이 생길 때 |
| 주먹 | 몸 낮춰 모으기(붕권·충전 준비) · 양팔 벌려 포효(포효·도발) · 공중 연타(공중 연타·백열권) · 내려찍기 주먹(지면 강타·천붕격) · 방어 자세(방어 자세·수호) |
| 쌍검 | 엎드려 웅크림(질풍·섬광 준비) · X자 교차(공중 난무·난무) · 회전(회선·칼날 폭풍) · 표식 던지기(표식·칼날 덫) |

- 몸 자체가 달라지는 경우(웅크림, 뛰어오름, 회전)는 다리 프레임 2~3개 + 위치 오프셋(포즈 body bob·lean)으로 처리. 회전은 바라보는 방향을 번갈아 바꿔서 표현 (회전 금지 규칙 유지): 회전베기 active·회오리 검기 active(+0.12초) 동안 0.06초마다 그림 방향만 번갈아 (fx.json playerMotion.spin, view/playerView.ts spinFacing, 판정 방향은 그대로)
- 같은 포즈를 쓰는 스킬끼리는 리듬·이동·이펙트로 구분 (docs/motion.md)
- 스킬별 포즈 배정은 shared/data/skills.json의 poses 필드. 계열 스킬을 데이터로 옮길 때 함께 정한다

- 포즈마다 앞팔(필요하면 뒷팔)만 다시 그리고, **손 위치를 기준점**으로 무기를 붙인다
- 무기·팔 방향은 8방향(가로·세로·45°)만 사용 → 선이 깨지지 않음. 연속 회전 금지
- 같은 종류의 다른 디자인 무기는 무기 마스크만 교체
- 무기 외형 3등급: 제작(층 테마 재료 모양 — 예: 버섯 갓 가드 대검), 보스(보스 테마가 강하게 드러남 + 스미어 색 변경), 색 변형(팔레트만 교체)
- 층마다 제작 4 + 보스 1 = 외형 5개. 같은 검토 절차(사양 → 실루엣 → 색)
- 포즈는 어떤 의상에도 그대로 적용 (레이어 구조)

### 행동 구간과 포즈 연결
- windup → 준비 포즈, active → 공격 포즈 + 스미어(7장), recovery → 공격 포즈 유지 후 대기로
- 대검 충전 중(준비 끝에서 멈춤, skills.md 2장) → skills.json poses.charge (SK-3 2차): 머리 위로 준비하지 않는 대검 스킬 8개 = 충전 포즈 charge(허리 옆 쥐기: 몸 1px 낮춤·다리 벌림, 두 손을 허리 높이에 모아 쥐고 칼끝은 뒤로 수평), 대지가르기·지진은 poses.charge 없음 = 머리 위 치켜들기 그대로
- 구간 길이는 데이터(weapons.json, skills.json)가 기준. 포즈는 구간에 맞춰 바뀌므로 공격 속도를 바꿔도 그림은 수정 불필요
- 걷기는 다리 2프레임(좁은 보폭·발 들기)을 4박자로 번갈아 순환, 디디는 박자에 다리를 뺀 몸이 1px 내려감. 팔·무기는 흔들지 않는다 (서기는 멈췄을 때만)

### 이동·상태 모션 (캐릭터 공통, 1-8c: 새 다리 그림 없이 기존 프레임 + 몸 내림·기울이기·누움으로 표현, 형식 sprites.md 5장)
| 모션 | 프레임 | 표현 |
|---|---|---|
| 대기 숨쉬기 | 2 | 몸통·머리 1px 오르내림 (breathe) |
| 걷기 | 2 + 몸 내림 (확정) | 좁은 보폭 ↔ 발 들기, 디딜 때 몸 1px 내려감 |
| 달리기 | 4 | 몸 앞으로 기울임 (run1~4: 걷기 다리 + 상체 앞 1px + 몸 내림). 다리 폭·스카프 날림은 전용 그림이 필요해 보류 |
| 방향 전환 | 1 | 휙 돌아서는 순간 (turn: 몸 1px 내림 + 발밑 먼지. 정면 그림은 보류) |
| 백스텝 | 2 | 뒤로 뛰는 자세 → 착지 (backstepAir: 발 든 다리 + 상체 뒤 1px / backstepLand: 웅크림. 높이는 위치 오프셋 연출) |
| 대시 공격 | 1 | 무기별 전용 포즈 (무기 포즈 세트에 추가). 그리기 전까지 대검은 idle(칼 수평) → slash 포즈 + 찌르기 스미어 |
| 피격 | 1 | 몸 뒤로 젖힘 + 피격 표정 (hurt: 상체 뒤 1px) |
| 다운 | 1 | 눕힘 (down: 재질 격자를 돌려 음영을 다시 입힌 누운 자세. 그림을 회전하지 않음) |
| 기상 | 2 | 무릎 짚기 → 서기 (getup: 웅크림 0.3초 → 서기) |
| 쓰러짐 | 1 | 엎드림 + 머리 위 별 (knocked: 엎드려 누운 자세 + 머리 위를 도는 금색 별 3개) |
- 다리·몸 프레임이라 무기 포즈와 조합. 피격 중에는 무기 대기 포즈, 다운·쓰러짐(누움) 중에는 무기를 그리지 않음
- 점프 없음 (combat.md 3장)

## 5. 자동 음영 규칙 (모든 스프라이트 공통)

마스크(재질 글자)만 그리면 아래 규칙으로 음영·외곽선을 자동 생성한다.

### 색 램프
- 재질마다 4단계: 밝음 / 기본 / 그림자 / 가장 어두움
- 밝음: 색상을 노랑(55°) 쪽으로 10° 이동, 명도 +11%p
- 그림자: 색상을 파랑(255°) 쪽으로 14° 이동, 명도 −12%p
- 가장 어두움: 색상을 보라(265°) 쪽으로 24° 이동, 명도 −25%p
- 기본색은 palette.json 값

### 광원과 음영
- 빛은 왼쪽 위에서
- 윗면·왼쪽 위 가장자리 → 밝음
- 아랫면·오른쪽 가장자리 → 그림자
- 세로로 이어진 같은 재질의 아래쪽 약 30% → 그림자
- 다른 재질 바로 아래 한 줄 → 그림자 (모자·앞머리·버섯 갓 아래 그늘)
- 16px 캐릭터는 음영을 최소한으로 (과하면 지저분함). 큰 스프라이트(정예·보스·배경)는 그림자 경계에 디더링(체크무늬) 허용. 몬스터는 가로 30px 초과 프레임에 적용하고, 체크무늬는 발밑 줄 기준으로 맞춰 프레임이 바뀌어도 무늬가 흔들리지 않게 한다

### 외곽선
- 스프라이트 바깥 1px
- 아래·오른쪽(빛 반대편) 외곽선: 공통 외곽선색 (palette.json global.outline)
- 위·왼쪽은 해당 재질의 "가장 어두움" 색 → 딱딱하지 않은 색 외곽선
- 눈·볼터치 같은 고정색 픽셀은 음영 없이 그대로

## 6. 몬스터와 환경

### 몬스터 크기
| 등급 | 키 | 예 |
|---|---|---|
| 일반 소형 | 10~12px | 통통버섯 (캐릭터보다 조금 작게) |
| 일반 중형 | 18~22px | 아기 멧돼지 (34 × 21) |
| 정예 | 24px 전후 | 갓버섯 기사 |
| 보스 | 40~64px | 졸린 이끼곰 (46 × 60) |

- 졸린 이끼곰 외형 (2026-10 다시 그림, 승인 캡처 floor1_monsters.png보다 데이터가 우선): 크고 둥근 머리·하이라이트 있는 동그란 눈·볼터치·짧은 주둥이·웃는 입, 둥근 몸·동그란 배, 등 이끼 덩어리 + 머리 뒤 이끼 갈기, 버섯 2개. 머리와 몸은 선을 긋지 않고 같은 털색의 다른 재질 글자(f 몸 / F 머리)로 나눠 자동 음영의 턱 아래 그림자로 구분한다
- 아기 멧돼지 외형 (2026-10 크게 다시 그림 19 × 14 → 34 × 21, 승인 캡처 floor1_monsters.png보다 데이터가 우선): 돼지와 구분되게 높은 어깨 혹·정수리부터 등까지 짙은 갈기(삐죽 털)·길게 좁아지는 쐐기 머리와 앞 코·위로 휜 엄니. 통통하게: 둥근 몸통·처진 크림 배·짧고 굵은 다리·볼살. 엉덩이 위 작은 이끼. 줄무늬는 자동 음영을 끊어 얼룩져 보여 쓰지 않는다
- 확대해서 쓰지 않는다. 크기가 다른 같은 종류(장식용 작은 버섯 등)는 그 크기로 따로 그린다
- 동작은 모양을 바꾼 프레임으로 표현 (찌그러짐·늘어남도 프레임). 회전은 90° 단위만 (이끼곰 구르기)
- 판정 크기와 겉모습 크기를 최대한 일치
- 실루엣만으로 종류가 구분되게. 공격 준비(windup) 중에는 공격 부위가 커지거나 깜빡임

### 바닥과 벽 — 땅 밑 숲 (2026-10, client/src/view/roomBg.ts)
돌벽·돌 타일 대신 숲으로 바꿈 (딱딱하고 밋밋하다는 피드백). 승인 데모 floor1_room_hud_mockup.html의 벽돌·바닥 타일은 이 결정으로 대체 (HUD 부분은 그대로 기준). 색은 1층 팔레트 기존 색만 쓴다
- 위쪽 잎 덮개: 둥근 잎 뭉치가 겹친 아래 가장자리, 가장자리에 밝은 잎결. 작은 잎이 번갈아 달린 곧은 넝쿨이 드문드문 (구불거리는 뿌리는 쓰지 않음 — 징그러워 보임)
- 뒤쪽 벽 자리(30px): 먼 숲(어두운 잎 덩어리·가는 줄기 디더링) → 굵기 제각각인 나무줄기(나무껍질 줄, 밑동이 벌어진 뿌리, 이끼 한 덩이) → 그 앞 둥근 덤불 두 줄(뒤 줄 어둡게, 앞 줄은 왼쪽 위 밝음), 바닥 위로 살짝 걸침
- 바닥: 격자 없는 풀밭. 큰 얼룩 3단계(경계만 2×2 디더링), 흙 자리, 잎 사이 햇빛 얼룩(빛줄기 색 18% 바둑판), 풀 포기·클로버·작은 흰 꽃·돌멩이. 몬스터보다 눈에 띄지 않게 낮은 대비
- 덤불 앞 바닥에 얕은 디더링 그늘. 방 깊이가 얕으면 아래는 어두운 흙 가장자리
- 앞쪽 벽·덤불은 그리지 않는다 (캐릭터를 가리는 전경 금지). 앞쪽 소품은 낮게
- 방 문은 뒤쪽 벽 자리에 선 나무 아치 (들어온 문 = 왼쪽 끝, 출구 = 오른쪽 끝, 30px 안에 들어가는 높이). 닫힘은 어둠 + 덩굴, 열림은 빛 테두리 (그림 sprites.md 11장)
- 우물에서 떨어지는 방(rooms.json wellDrop): 입장 지점 위 잎 덮개에 구멍이 나 있고, 구멍에서 입장 지점까지 버섯빛 빛줄기(바둑판 디더링 35%). 밧줄은 없음

### 섬
- 던전과 같은 규칙, palette.json island 색 (밝고 따뜻하게)
- **디오라마 구조**: 잔디 평지 → 모래사장 → 앞쪽에 흙·바위 절벽 단면 → 바다. 섬 앞쪽 가장자리에서 단면이 보인다
- 잔디: 타일 경계선 없이(던전 바닥처럼 깎인 판이 아님) 두 잔디색을 아주 옅게 깔고, 밝은·어두운 점과 풀 포기를 흩뿌림. 섬 화면은 둥근 얼룩(큰 얼룩 + 작은 굴곡 값 노이즈, 경계는 한 칸 걸러 섞기)으로 깐다 — 승인 데모의 16×10 번갈아 깔기는 넓은 섬에서 바둑판으로 읽혀서 바꿈 (client/src/view/islandGround.ts grass, 개발 중 ?grass=checker로 비교)
- 길: 흙길 색에 자갈 점. 모래: 위 가장자리 한 줄 밝게
- 물: 2프레임 반짝임 + 해안선 하얀 거품 (0.5초 간격)
- 선착장: 남쪽 흙길 끝에서 모래·절벽 위로 나온 나무 잔교(가로 판자, 물속 기둥 2개) + 밧줄로 묶어 둔 작은 배. 바닥 높이 배경 사물이라 캐릭터가 위에 선다

- 고정 시설: 우물(던전 입구: 돌 테두리 + 나무 들보에 매단 도르래·밧줄, 물 대신 아래에서 버섯빛이 새어 나오는 구멍(가운데 노랑 → 이끼색 → 어둠), 넝쿨·작은 버섯, 떠오르는 포자 2프레임. 지붕은 없앰 — 물 긷는 우물로 읽히지 않게, 2026-10), 잡화점(줄무늬 차양 노점, 진열된 물약), 무기 거치대, 게시판(쪽지), 공용 창고(작은 헛간)

- 분위기: 풀 2프레임 살랑임, 나비, 물 반짝임, 구름 그림자. 밤낮 변화는 MVP 이후

- 사물은 캐릭터와 같은 1px 외곽선 (외곽선색)

- 사물 땅 그림자 (2026-10, client/src/sprites/castShadow.ts, 값 fx.json islandShadow): 바닥 높이 사물(선착장·돌길)을 뺀 모든 섬 사물. 그림 실루엣을 높이만큼 오른쪽(× shear)·뒤(화면 위, × lift)로 옮겨 바닥에 눕힌 모양 + 맨 아래 줄 밑 접지 줄 1px. 안쪽 채움·경계 바둑판, 색 global.outline 반투명. 바닥·구름 그림자 위, 사물·캐릭터 아래 (깊이 −997)

### 색 규칙 (HSL)
| 대상 | 채도 | 명도 |

- 소품(지붕·차양·철 등)·포인트 색(코·발굽·배 등)·고정 의미 색·이펙트 보조색(global.fx: 번쩍임, 스미어 바깥 금색, 먼지, 충격 링)은 범위 검사 대상이 아니다 (hex 형식만 검사)
- 범위는 승인 색(모래 S63, 통통버섯 갓 S77, 플레이어 노랑 S86, 멧돼지 대비 18.6%p)에 맞춰 넓힌 값

- 모든 hex 값은 **client/data/palette.json 한 곳에만**. 문서·코드에 하드코딩 금지
- 새 색을 추가하면 `pnpm palette-check`로 규칙 검사. 어떤 경로가 어느 역할인지, MVP 밖 층(경고만)은 tools/palette-check/rules.json (범위 값은 이 표와 같게 유지)
